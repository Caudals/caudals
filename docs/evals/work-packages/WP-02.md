# WP-02 — tenant evidence persistence and private storage

Status: deployed and in production use since 2026-09-23; later packages build on it. Specification: draft v0.1, base commit `9c5b33b`. The notes below describe the original foundation work.
Foundation work was completed in the isolated `evals-foundation` worktree. No
production deployment or production data change was performed.

## Implemented

- Migration 032 depends on 031's `evals.workspace`, transaction settings `evals.org_id` / `evals.actor_id`, and non-owner `evals_runtime`. All evidence tables force tenant RLS; tenant relationships use composite foreign keys. Immutable revisions, manifests, release membership and source chunks reject updates/deletes at the database layer. Artifact metadata freezes on finalization. FK and keyset pagination indexes are included.
- Project creation/listing; target configuration revisions; CEF-validated case/rubric/output-schema/tool-fixture revisions; source upload/finalization/revision creation; bounded source excerpt/anchor reads; suite creation, optimistic draft editing, immutable freeze/read. Existing contract schemas and canonical hashing are imported directly, not duplicated.
- Mutating creation routes require actor/tenant/route/payload-scoped `Idempotency-Key`; reuse with a different canonical payload conflicts. Suite drafts use an explicit expected version. Freeze validates referenced revision hashes, project ownership and family splits in PostgreSQL.
- Authenticated app upload/download gateway under `/api/evals/v1/artifacts/:id`. Upload sessions return an app-relative `PUT /artifacts/:id/upload?orgId=...` route. No S3 URL, bucket, endpoint or object key reaches the caller. Each request authorizes workspace scope; every object lookup is tenant-scoped before storage I/O. Private evidence, drafts and source reads require write-level workspace access, so report viewers do not implicitly get private evidence exports.
- Gateway upload is bounded to 1 MiB and checked against declared size/SHA-256. Finalization reads/verifies and extracts outside a database transaction, seals bytes at a fresh create-only key, then briefly locks/rechecks state and commits the immutable revision. Download checks metadata, retention, size and SHA-256 before returning an attachment with `nosniff`, private/no-store headers. Upload retries cannot alter sealed evidence.
- UTF-8 plain text, Markdown and DOCX are the initial supported formats. DOCX preflights ZIP directory counts/sizes/ratios/offsets; rejects encrypted, ZIP64/multi-volume, macro/embedded-object packages; inflates only the required parts with a hard actual-output ceiling; rejects DTDs and deep/malformed XML. No network fetches, macro execution, Office interpreter, HTML rendering or external entity resolution. Excerpts are at most 4096 UTF-16 code units without splitting surrogate pairs. Original artifact hashes, extractor versions, stable anchor IDs, extracted-text offsets and normalization metadata are preserved.

## API workflow

1. `POST /projects` with `orgId`, title, description.
2. `POST /sources/uploads` with `orgId`, `projectId`, title, mediaType, byteSize, sha256, rights, optional visibility (defaults internal) and safe exportPath. PUT raw bytes to returned app route, then `POST /sources/:id/finalize` with `orgId`.
3. `GET /sources/:id?orgId=...` returns revision metadata and the newest revision's bounded anchors; `GET /artifacts/:id?orgId=...` returns an attachment, never a storage URL. `POST /sources/:id/revisions` binds a new immutable source revision to a finalized same-project artifact.
4. `POST /projects/:id/revisions` takes `kind: case|rubric|output_schema|tool_fixture` and a complete CEF document. CEF persisted entity/revision IDs are UUIDs. `POST /projects/:id/targets` takes a validated config and optional existing targetId; credentials are rejected until secret-service binding is wired.
5. `POST /suites`; `GET/PATCH /suites/:id/draft`; `POST /suites/:id/versions` with expected version; `GET /suites/:id/versions/:versionId`. Freeze preserves the original CEF manifest and exact membership.

## Deliberate foundation limits

PDF, legacy DOC, XLSX, HTML, encrypted archives, OCR and arbitrary archives return unsupported/malformed errors. PDF needs a separately isolated document worker; this is not full document-ingestion acceptance. DOCX extracts main-document text only, not headers, footnotes, comments, images or layout; anchors refer to the declared extracted-text representation, not page coordinates.

CEF projection/bundle conformance belongs to the contracts agent. This slice does not implement export jobs, publication, external target execution or secret service integration. Freeze resolves complete CEF bundles through the contracts validator, including output schemas and deterministic tool fixtures, and binds manifest files to finalized same-project private artifacts in immutable suite-artifact rows. Candidate attachments additionally require explicit candidate visibility at upload. No tool fixture runtime is executed. Retention metadata is recorded (pending seven days, accepted ninety days); expiration/deletion scheduling, report evidence pins and backup expiry belong to the lifecycle work package. Failed finalization can leave an unreferenced sealed object; object cleanup must reconcile DB references before applying pending-object retention. This slice never claims that cleanup is already running.

Migration rollback deliberately refuses destructive deletion of immutable evidence. Recover by restoring a pre-migration backup in an isolated database or reviewed forward repair after evidence reconciliation; do not run DROP/CASCADE on production evidence.

## Validation

`tests/evals/storage.test.ts`: valid UTF-8/DOCX, anchored extraction, binary/HTML/invalid UTF-8, size bounds, macros, DTDs, nesting, malformed XML, declared and actual decompression bombs.

`tests/evals/evidence.api.test.ts`: app gateway authorization, forged tenant headers, private attachment responses, upload byte limits and unsupported PDF requests.

`tests/evals/storage.integration.test.ts`: disposable MinIO write/read/checksum, identical retry, create-only seal and anonymous denial. Requires `EVALS_TEST_S3_ENDPOINT` pointing at loopback.

`tests/evals/evidence.test.ts`: live nonowner PostgreSQL RLS, guessed IDs, cross-tenant FK rejection, optimistic updates, immutable revision/manifest enforcement and pooled transaction scope reset. Requires already-applied 031/032 and `EVALS_TEST_DATABASE_URL`; uses rollback-scoped fixtures and never changes schema.

`tests/evals/evidence.storage.test.ts`: full repository upload/finalize/download/source revision lifecycle plus guessed-object isolation and arithmetic/tool-fixture suite freezes with immutable revisions, using the disposable DB/runtime/MinIO. Requires both test URLs and optionally `EVALS_TEST_RUNTIME_DATABASE_URL`. It leaves uniquely named immutable fixture evidence in the disposable database; it does not disable guards to delete evidence.

## Integrated acceptance result

Migration 032 was applied after 031 in disposable PostgreSQL 16. The complete
Stage A suite passed with real loopback PostgreSQL and MinIO: 144/144 evaluation
tests, including 86 CEF cases, the repository upload/finalize/download lifecycle,
private object denial, tenant RLS, pooled-context reset, immutable frozen suite
membership and source-anchor traceability. TypeScript and ESLint also passed.

`032_evals_evidence_down.sql` was executed against the disposable migrated
database and refused destructive removal as designed. Recovery is a reviewed
forward repair or verified backup restore. Production private object storage,
expiry cleanup and restore rehearsal remain release prerequisites; Stage A does
not claim those services are deployed. WP-02 acceptance criteria are satisfied
in the isolated environment. Next: WP-03.
