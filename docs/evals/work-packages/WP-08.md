Status: deployed. App, general, browser, scheduler and document workers run from immutable digests. ## Delivered operator flow

`/ops` now exposes client selection, evaluation preparation, review, runs, reports and platform navigation. `/ops/evaluations` creates clients/projects, connects an API, creates evaluations and previews response imports. `/ops/review` projects preparation review states. `/ops/runs/:id` shows the frozen plan hash, phase/timeline, case-unit outcomes/reasons/attempt IDs and reserved/settled/unresolved costs. `/ops/reports` shows publication state. `/ops/platform` describes the separate privileged provider/budget control boundary rather than exposing secrets.

The complete API path is client → project/source/target → context questions → grounded suite draft → explicit freeze → connection/import → durable run → score/review → immutable report → publish → authenticated export/private share. `npm run evals:demo-stage-b` runs the clearly labeled synthetic calculation slice without customer data or an external call.

## Lifecycle and recovery controls

- `retention_job` separates artifact expiry/deletion, share revocation and report withdrawal. Actions append minimal immutable `recovery_control_event` records; artifact objects are deleted before metadata becomes `deleted`.
- Recovery control events cover share, credential, artifact, report and workspace actions. `npm run evals:export-recovery-ledger -- /absolute/private/path.jsonl` creates a new mode-0600 ledger file for independently retained encrypted storage.
- `npm run evals:recovery-rehearsal -- <snapshot-UTC>` refuses to run with dispatch enabled, imports the newer ledger, replays controls before reads, records verification evidence and leaves workers paused. `replayRecoveryControls` never restores deleted content or re-enables a revoked grant/credential. Both commands are registered in `package.json` and load the React-server condition required by the `server-only` lifecycle module.
- `npm run evals:release-check` verifies Stage B migrations and non-privileged service roles while dispatch is disabled. `--dispatch-reviewed` is required to inspect a configuration with dispatch enabled.
- Migrations 034–038 are additive. Their down files refuse destructive rollback. Roll back code by disabling queues and restoring the prior compatible image; preserve attempts, costs, evidence and lifecycle records.

## Release procedure

1. Build immutable web, general-worker and Playwright document-worker images on a runner with adequate memory. Do not build under host pressure.
2. Verify a recent local backup on the VPS and execute the restore rehearsal with the independently retained control ledger.
3. Apply 034–038 with the explicit migration-owner command and advisory lock; apply `worker-grants.sql` and `document-grants.sql` only to their separately provisioned NOBYPASSRLS service roles.
4. Deploy workers with dispatch/documents disabled, explicit workspace allowlists, private DB/queue/storage credentials, resource limits and log rotation.
5. Run tenant/host/secret/budget tests, storage probe, a synthetic demo and one tiny evaluation against a Caudals-controlled synthetic system. Visually inspect its PDF.
6. Enable only the evaluated workspace, watch queue age, leases, target errors, spend reconciliation, disk/RAM and backup age, then perform a second compatible run/comparison.
7. Confirm marketing and Leads CRM health before widening invite-only access.

Production-only evidence still required: local backup and full identity/object-storage restore proof, resource headroom under a run, marketing/CRM latency comparison, and the unshipped connection and scheduling gates described in WP-09–13. A full app-created synthetic API evaluation, scored rerun and compatible comparison, queued PDF export and authenticated download, restricted share/revocation, a long-response PDF check, an object-storage round-trip, immutable worker digests, a tiny DGX queue probe, and marketing/CRM HTTP health checks pass. Customer workspaces remain outside the worker allowlist. Migration 046 adds a pre-dispatch target invocation usage ledger; production acceptance of that migration and worker version is recorded after deployment.
