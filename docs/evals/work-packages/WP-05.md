# WP-05 — Context understanding and bounded generation

Status: ready_for_review. Production automatic preparation is enabled only for explicitly assigned workspaces and routes both context analysis and case drafting to the internal DGX provider. Generated cases remain private and review-gated; freezing still requires operator approval.

## Delivered

- `buildContextProfile` records purpose, users, tasks, source authority order, date/jurisdiction, risk, capabilities and versioned prompt/model identity. Date-sensitive missing context and contradictory source claims create explicit critical questions.
- `POST /api/evals/v1/evaluations/:id/context` stores an immutable profile revision and durable questions; `GET` restores profiles, questions, generation batches and quarantine after browser/worker restart. Question answers are durable at `/context/questions/:questionId`.
- `GenerationWorkflow` implements extract → profile → plan → draft → reference-build → validate → review → freeze checkpoints. Input hashes make completed steps reusable. DGX/model/budget outages pause; retries stop at three and quarantine invalid output.
- Coverage planning is seeded and bounded to 500 cases. Generated-case validation requires valid CEF, existing anchors, source links for source-supported claims and unique families; family fingerprints detect near-duplicate numeric variants.
- `POST /api/evals/v1/evaluations/:id/generate` creates a generic grounded-QA rubric and source-linked cases from an operator-approved source/question set. It records the generation batch and prepares a complete immutable manifest in a versioned suite draft. The existing suite freeze endpoint performs the explicit release action after review.
- `syntheticAccountingFixture` is Caudals-owned synthetic data for repeatable smoke checks. It is never presented as customer evidence.

## Review/freeze contract

Preparation stops in `needs_input` for critical unknowns and in `needs_review` for generated drafts or quarantined output. References/rubrics are not candidate-visible. The operator reviews the source/case/rubric records through the preparation projection, then freezes with `POST /api/evals/v1/suites/:id/versions` using the draft version. Frozen source/case/rubric identities cannot be mutated.

No unapproved cloud fallback exists. Provider routing, budget and DGX model revision are frozen through WP-03. The deterministic grounded-pack path lets a managed evaluation proceed when narrative/DGX generation is unavailable.
