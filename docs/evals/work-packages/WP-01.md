# WP-01 — Application shell, host routing and identity

Status: ready_for_review. Specification: draft v0.1, base commit `9c5b33b`.

## Prerequisite evidence

WP-00 records the existing Better Auth, proxy, deployment and resource
contracts. Development used the isolated `codex/evals-foundation` worktree,
loopback PostgreSQL, synthetic identities and loopback browser previews. No
production migration, identity grant or deployment was performed.

## Implemented behavior

- `app.caudals.com` routes `/evaluation-entry`, `/ops`, `/workspace`, and
  `/api/evals/v1` through a separate English evaluation surface. Unknown hosts
  fail closed. Marketing and the existing `/admin` surface retain their current
  routes and locale behavior.
- Existing Better Auth sessions are reused. Evaluation authorization comes from
  explicit `evals.platform_role` and tenant membership records, resolved again
  in every API handler. Proxy routing is not an authorization boundary.
- A platform operator can create clients without accounts, create and revoke
  one-time invitations, and view only the client list permitted by the role.
  Invited users either authenticate an existing verified account or enroll a new
  account through the invitation transaction. Cross-tenant IDs return 404.
- Invitation bearer values remain in URL fragments, are removed from browser
  history after consumption, and are never accepted from query parameters.
  Sign-in preserves the fragment locally. Recovery excludes the bearer from the
  emailed callback URL.
- The shell has role-aware navigation, keyboard focus/skip behavior, responsive
  drawer/sidebar layouts, explicit empty/error/loading states, and a visible
  Better Auth POST sign-out action with failure/retry behavior. Hidden Stage B
  features do not appear as dead navigation.

## Schema and API contracts

Migration `031_evals_identity.sql` adds workspace, membership, invitation,
platform-role, audit and idempotency records under forced RLS. Runtime access is
through a non-owner NOBYPASSRLS role and transaction-local `evals.org_id` /
`evals.actor_id`. Narrow security-definer functions use fixed search paths and
have PUBLIC execution revoked.

Evaluation APIs are rooted at `/api/evals/v1`. Mutations require same-origin
requests and bounded duplicate-key-rejecting JSON. Workspace creation and
invitation creation use actor/route/payload-scoped idempotency keys. Direct
route calls repeat role checks. Error responses do not reveal whether a guessed
cross-tenant object exists.

## Tests and UI evidence

- `npx vitest run proxy.test.ts tests/evals/routing.test.ts --maxWorkers=1
  --minWorkers=1`: 9 passed. This covers unknown/app/marketing hosts, direct
  routes, redirect safety and bounded JSON parsing.
- Real PostgreSQL identity suite: 7 passed with the non-owner runtime role,
  covering two-client isolation, invitation replay/expiry/revocation, bearer
  non-persistence, pooled-context reset, owner refusal and enrollment.
- `npx playwright test --config=e2e/evals/ui.config.ts`: 24 passed. It covers
  client/invitation operations, session expiry, actual Better Auth sign-in and
  TOTP calls, recovery/reset, mobile and desktop shells, sign-out success and
  failure, and fragment-only invitation handling.
- A separate real Next/PostgreSQL browser run created two clients, enrolled a
  viewer into only one, rejected guessed reads/mutations for the other, rejected
  CSRF, and verified English layouts at 390, 768 and 1440 px.
- Reviewed screenshots are in `docs/evals/design`, including runtime operator,
  workspace and sign-in states. No horizontal overflow was observed at the
  tested widths.

## Deployment, rollback and limits

Deployment status: deployed on app.caudals.com with additive migration 031.
The current main image serves the evaluation shell and APIs; synthetic identity,
invitation, role and tenant-isolation paths are exercised in the production
records under WP-08 and WP-11. Its down file refuses destructive identity
removal; recovery uses a reviewed forward repair. Existing `/admin` remains
available and retains a gated link for users who also hold an evaluation
platform role.

Stage A intentionally has no run/report navigation. Founder role provisioning
remains an operator release action. Off-host backup and restore are deferred on
the user's direction; they are not represented as completed. WP-01 acceptance
passed in isolation and the deployed identity path has synthetic production
evidence. Next: WP-02.
