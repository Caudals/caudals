## Shared contracts

- Parent migrations 031/032 own identity/domain. `execution_workflow.run_id` is a
  frozen logical domain ID; this slice references `workspace(id)` directly and
  enforces composite tenant references internally.
- `withTenant({orgId,actorId}, callback)` and `getEvalsPool()` are parent-owned.
  Domain credentials must be non-owner, non-superuser, NOBYPASSRLS.
- `enqueueInvocation(client, tenant, {workflowId,runId,planHash,kind,version,input})`
  must run inside the same transaction as domain plan freezing. Supported
  inference queues are execute_api/generate/profile/grade. Other queue names are
  created but deliberately have no placeholder consumers that could drop work.
- `InvocationWorker.handle` returns after durable output/state/cost commit. Queue
  bodies contain tenant/step IDs and the input hash only. Tenant workers have an
  explicit operator-configured workspace allowlist. No cross-tenant discovery.
- `controlWorkflow(client, orgId, workflowId, 'pause'|'resume'|'cancel')` is the
  action API after server-side authorization. `execution_event.id` is a durable,
  monotonic cursor for an API projection, not a stream of raw provider logs.
- pg-boss is pinned in the lockfile to **12.33.1**. Queue schema must
  explicitly match EVALS_ENV: `evals_queue_dev` or `evals_queue_prod`. Its login
  owns only a separate queue schema/database and has no domain-table grants.

## Executables and configuration

Build separately with `docker build -f infra/evals/Dockerfile -t <image> .`.
The standalone Node 20 image deliberately retains lockfile-pinned tsx so both
entrypoints run; it does not rely on the web image retaining dev dependencies.
GitHub Actions builds worker images on relevant `main` pushes. Production uses
immutable image digests. The general worker is deployed with resource limits;
the example Compose file remains disabled by default.

Worker: `services/evals-worker/start.sh` from repository root. Required variables:

- `EVALS_ENV`, `EVALS_QUEUE_SCHEMA`, `EVALS_DISPATCH_ENABLED=true`.
- `EVALS_DATABASE_URL_FILE` for the separate evals_worker identity.
- `EVALS_QUEUE_DATABASE_URL_FILE` for the separate queue identity.
- `EVALS_WORKER_ACTOR_ID` and `EVALS_WORKER_ORG_IDS` (JSON UUID array).
- `EVALS_MASTER_KEYRING_FILE`: JSON map of key-version to base64 32-byte key.
- `EVALS_DGX_ENDPOINT_FILE`: protected admin-configured endpoint, required for DGX.

Apply `infra/evals/worker-grants.sql` after provisioning evals_worker without
ownership/BYPASSRLS. Never make it a member of the web role. The master key file
belongs only to invocation/configuration containers. No production secrets are
copied into development. Commercial adapters require HTTPS and pin validated
public DNS addresses to the actual connection; redirects are never followed.
DGX requires an exact protected endpoint match and is not a customer SSRF bypass.
Actual private-route authentication and network enforcement remain deployment gates.

Admin: `services/evals-worker/admin.sh <command>` reads configuration JSON from
stdin and prints IDs only. Provision **evals_execution_admin** separately using
`infra/evals/admin-grants.sql`; it must not inherit evals_runtime. Configure
`EVALS_ADMIN_DATABASE_URL_FILE`, `EVALS_ADMIN_ACTOR_ID`, `EVALS_ADMIN_ORG_ID`.
The actor must be an existing platform_admin in 031; withTenant rejects owner
credentials. Exposed service methods live in `lib/evals/providers/admin.ts` and
accept a scoped PoolClient + tenant. Parent API routes must apply recent-auth
platform-admin authorization and use the dedicated configuration pool; never
expand web role access to endpoints, envelopes or global provider caps.

Commands / service methods:

| Command | Method | Input |
| --- | --- | --- |
| account | registerAccount | name, currency, ceiling decimal string, enabled |
| provider | registerProvider | providerConfigSchema; immutable revision and exact admin DGX endpoint |
| price | registerPrice | priceConfigSchema; prices are currency **per token**, tools per invocation |
| budget | setBudget | kind provider/workspace/run, scopeId, currency, ceiling, optional enabled for provider |
| secret-write | writeSecret | purpose, scopeId, keyVersion, optional recordId for rotation |
| secret-revoke | revokeSecret | recordId |
| probe | enqueueProbe | invocationSchema; existing run/workspace budgets and immutable provider/price refs |
| reconcile | reconcileUnknown | attemptId, actual decimal string, evidenceId |
| control | controlWorkflow | workflowId, action pause/resume/cancel |

For secret-write, plaintext comes only from `EVALS_SECRET_VALUE_FILE`, not argv or
JSON. Mount `EVALS_MASTER_KEYRING_FILE`; rotations append encrypted versions.
Revocation rejects future invocation decryption, including old versions. It does
not claim to cancel calls already accepted. The browser executor never receives
these master keys or platform credentials.

Probe setup: register disabled account, immutable DGX revision with explicitly
approved tiny probe (`probeApproved: true`, unknown features false), zero external
prices with recorded source, then workspace/run caps. Enable account and enqueue
probe with <=128 output tokens, <=256 input-message bytes and a nonzero internal
cost-per-second estimate. A normal invocation requires verified text/bounded-token
capabilities. A probe result does not automatically enable capabilities; an admin
records new revisions based on observed evidence. Never infer tool/JSON support
from inventory or a successful text answer. Commercial probes are not enabled by
this unverified DGX-only exception.

## Recovery and accounting

Every attempt atomically acquires provider capacity and reserves against provider,
workspace and run caps. Numeric(24,9) storage plus bigint nano-unit calculations
avoid binary-float currency arithmetic. Prices are immutable revisions. Input
reserves the full configured context minus maximum output; configured model
bounds must be validated before commercial routing is enabled. Tool calls and
unbounded provider work are unsupported in this slice. No silent fallback.

A reserved-but-undispatched expired attempt releases its reservation and can
retry within the three-attempt bound. A dispatching expired attempt becomes
unknown: retain liability and capacity slot, fence the old worker, never replay.
Transport errors/5xx/malformed accepted responses conservatively follow the same
unknown policy. Explicit throttling may retry twice with backoff, jitter and
Retry-After; each rejected attempt conservatively settles its bounded estimate
and a retry needs a new reservation. Unknown invoice reconciliation takes admin
recorded evidence, settles the original liability and releases capacity. It
never requeues the old step; a deliberate new frozen plan is needed to invoke
again. Settlements above estimates record genuine costs and block further spend.

Pause/cancel is checked after reservation and before dispatch. In-flight work may
complete and settle. Completed observations/results and frozen inputs/plans are
DB-immutable. An incomplete provider response is preserved with finish reason,
marked failed at unit level and projected as partial when usable evidence exists.
Unknown steps never get a succeeded result. The adapter enforces an absolute
wall deadline including DNS and streaming body, response-size limits, and no
redirects. No transaction spans provider inference.

Recovery after restore: keep dispatch disabled; replay revocations/deletion
controls, review unknown reservations/provider slots, restore envelope keyring,
then enable explicit workspaces. The 033 down migration refuses destructive
rollback: do not delete liability/history to roll back code.


grant the domain worker login queue ownership or database CREATE. The queue test
verifies runtime restart after revocation. Runtime schema migrations likewise
require explicit offline maintenance; worker startup never self-migrates.

### Integrated probe contract for the parent

Migration 033 is final and ready after 032. Parent applies it once, then worker
and admin grant scripts (each role is separately provisioned, non-owner and
NOBYPASSRLS). Parent owns the real 031 actor/workspace setup and integrated probe.

The founder-approved probe bound is now **128 output tokens**, solely for
DGX-only probes with every external price equal to zero. Absolute timeout remains
at most 120 seconds. This gives the currently loaded reasoning model a chance to
finish without loading another model; truncation still remains explicitly
incomplete/unknown. Input-message bound remains 256 UTF-8 bytes.

Use the observed loaded `bluehawana/deepseek-v4-flash:iq2_m` model, not another
inventory model. Register contextLimit 262144 only based on the parent's current
`/api/ps` evidence. A tpm setting must cover the conservative full-context bound
for each planned probe (e.g. operator-approved 1000000 covers three sequential
262144-token reservations in one minute; it is a configured limit, not measured
throughput). Set concurrencyLimit 1. Use the protected mounted endpoint exactly.
Capabilities `{text:false,boundedTokens:false,probeApproved:true}` mean routing
is unverified and disabled except for the bounded admin probe. Do not interpret
those flags as measured lack of capability.

For each probeKind (`text`, `json_object`, `tools`), create a separate run UUID and
run budget, then call `enqueueProbe` with its price/provider/workspace budget IDs,
`routing:'local_only'`, permitted dataClass/region, harmless tiny messages,
`maxOutputTokens:128`, `timeoutMs:120000`, and an explicitly labeled operator
internal-cost estimate. The return is `{workflowId,stepId}`. Load only the queued
step's `input_hash` under the worker tenant scope and pass
`{orgId,stepId,inputHash}` to `InvocationWorker.handle`; the ordinary dispatcher
can deliver the same object through pg-boss. Inspect execution_result,
execution_attempt, budget_reservation, execution_cost_entry and provider_health.
No direct adapter calls are needed. Tool calls are inspected and never executed.
