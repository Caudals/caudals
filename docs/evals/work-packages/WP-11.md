# WP-11 — Minimal customer self-service

Status: invite-only journey implemented; synthetic production acceptance is partial; the Stage C release gate is not passed.

## Implemented locally

- `/workspace/evaluations/new` connects a supported target. The evaluation page can upload a private policy document, capture purpose/date and a source-backed example, generate a draft, display its question/approved answer/excerpt after reopening, freeze it and explicitly approve it before a run. The server rejects an unapproved or substituted suite and requires a ready connection. Source anchors are validated against the frozen source revision.
- Workspace summaries and runs poll for durable progress. The page supports cancellation and retry/assistance states; reports use a nonmodal desktop result inspector and a focus-managed mobile dialog. Usage and notification preferences are visible in settings; owners/editors/viewers are distinguished by server-side workspace checks.
- The manual-answer choice now creates an imported-response target without pretending to probe it. After source-backed questions are approved, a customer can start an awaiting-answers run, download a candidate-only CSV, upload a case-revision-matched CSV/JSONL/XLSX answer sheet, resume partial submissions, and publish a private preliminary deterministic report. Failed report finalization has a retry action after reopening. The import apply route checks the run's project, suite and execution mode before accepting observations; duplicated case revisions are rejected together.
- Run creation serializes active-run checks per workspace and enforces the server-side entitlement without granting runtime users update rights to funded limits. Suite approval is tied to its completed generation batch and project.
- Customer run and workspace-summary reads now expose progress, permitted usage and connection kind without returning internal plans, raw observations, connector credentials, operator events or cost ledgers. Creating a `reviewed` report revision requires a Caudals platform role; customer-created deterministic reports remain explicitly preliminary.
- The suite-fork API is workspace-write scoped and binds the requested frozen version to the suite ID, so an unrelated version cannot be forked through a misleading suite URL. The customer Test sets library at /workspace/test-sets lists frozen versions by project, and owner/editor members can fork into a separate draft. The editor at /workspace/test-sets/[id] updates non-holdout case text and expected answers as a new immutable revision, marks edits customer-supplied/unreviewed, and freezes a new version. Holdouts are not returned for editing or counted in the customer library.
- Browser contract checks cover source upload, preparation/reopen/approval, responsive keyboard access, result-inspector focus and account/invitation flows. These are isolated harness checks, not production acceptance.
