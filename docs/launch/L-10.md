## Implemented behaviour

- **Price book (migration 088).** `billing.price_book_revision` (draft → scheduled → active → retired, `effective_at`, multiplier and FX snapshot, `raises_prices`, `notice_sent_at`), `billing.model_rate` (µcr per 1M input/output/cached tokens by provider, model id and prompt-size tier, with the USD list price, FX, routing fee, EUR cost and source), `billing.action_rate` (the six §6.3 meters), `billing.fx_rate` (ECB) and `billing.price_check` (append-only weekly diffs). Rates change only on drafts; triggers reject edits, deletes and TRUNCATE on scheduled, active and retired revisions (only lifecycle columns move). The database enforces the 5-credit grid and the 10-credit floor. `ledger_entry` and `credit_hold` now reference the revision.
- **Revision in effect.** `billing.price_book_at(t)` is the latest non-draft revision with `effective_at ≤ t`, so a scheduled revision applies exactly on time; the scheduler's hourly job only relabels statuses. Revision 1 is in effect from 2026-10-11 (the §6.4 table and meters, ECB 1.1605 USD/EUR of 2026-08-19). Revision 2 is scheduled for 2027-01-01 with Google's announced Gemini 3.8 Flash increase (195 · 970 credits per 1M); its 30-day notice is due by 2026-12-02 (sender: L-16).
- **Lifecycle (platform admins, recent sign-in, `Idempotency-Key`, audited).** `POST /api/evals/v1/billing/admin/price-book/revisions` drafts from the revision in effect (list prices recomputed at the latest recorded FX, then per-model and per-meter changes); `GET …/revisions` (with every route's guard status) and `GET …/revisions/:id` (credits, margins, §6.4 run impact); `POST …/:id/schedule` (needs every meter and the local rate, must follow every other scheduled revision, keeps every current route priced, refuses an increase with less than 30 days' notice), `…/:id/cancel` (before it takes effect), `…/:id/activate` (a non-increase comes forward to now).
- **€0 guard (G9).** A trigger on platform, workspace and evaluation model routes raises `MODEL_PRICE_ZERO` for a non-DGX model with a €0 cost price and `MODEL_RATE_MISSING` for a model without a credit rate in the revision in effect or a scheduled one, unless the provider revision is an explicit `free_model` (new column, immutable like the rest of the revision; the two registered OpenRouter `:free` models were flagged). Settings → AI models shows each route's credit rate, a "€0 price · not for customers" badge, a €0 warning and a "This is a free model" choice in the model dialog. Providers & models shows the same per model revision and a summary warning. Local stays the default (D-09).
- **Estimator (§6.7).** `lib/billing/estimate.ts`, `POST /api/evals/v1/billing/estimates`. Exact meters (website 5, API 2, imported answer 1, pages 1 and 0.5, web searches 2 credits); engine tokens per role from 60-day platform-wide aggregates (`billing.estimate_stats`, aggregates only) per role and model from 20 samples, else per role, else the §6.7 seeds; p50 = n × mean per call, p90 = n × mean + 1.2816 × sd × √n; largest hold from the p90 token bound; ETA from seconds per question of completed runs (tail capped at twice the median below 20 runs). Inputs: the evaluation's approved test set and system (or given ids), optional model overrides per role, a test set to generate, sources to read. Output: p50/p90 credits and euros, largest hold, ETA, balance and the credits to add (none for contract workspaces, which run without holds). Editors (owner, editor, operator) and CI tokens (`runs:read`), `Idempotency-Key` required.
- **Prices over time.** The evals scheduler runs, hourly, price-book activation; monthly, the ECB USD rate (first working day after 15:00 UTC); weekly, the provider-price check (OpenRouter's public models API; Google-direct rows compared with OpenRouter's listing of the same model). Changes log `billing_price_check_changes`. `scripts/billing/check-provider-prices.ts` prints the same Markdown diff on demand. No paid calls.

## Backtest (acceptance: ±25 % on ≥ 80 % of historical runs)

`scripts/billing/backtest-estimates.ts` on read-only production aggregates (2026-10-12): for each finished run, the estimate the customer would have seen at its start (planned questions, judged questions, the frozen judge model, token statistics only from earlier calls) against what the credit engine would have charged (succeeded questions, completed engine calls at revision-1 rates, executed searches).

- **35 of 38 runs within ±25 % (92.1 %): target met.** Median absolute error 7.4 %; the actual cost was at or below the p90 estimate for 35 of 38.
- By connection: API 16/16, website 15/18, imported answers 4/4. Token statistics: seeded 24/24, per role 10/12, per model 1/2.
- Misses: two legacy runs from before frozen model routes (migration 078) had judge web research on that the estimate could not see (−29 %), and one partial run where 24 of 25 questions failed (failed questions are not charged; §6.8 refunds such runs).
- Excluded: 9 canceled, 4 failed, 2 paused, 1 empty and 8 operator-graded result sheets (operator work on managed contracts is free).
