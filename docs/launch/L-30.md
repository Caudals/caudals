## What shipped

- **Landing steps and FAQ.** Step 1 ("How it works") ends with the free test: eight questions written from your own website, checked in about three minutes. The FAQ's access answer describes the free test (public pages only, deleted after seven days). "How much does it cost?" now answers: the free test and the free account, pay-as-you-go credits in the app beyond the free plan, and pilot evaluations at a fixed price quoted before we start. No numbers (D-06). The same answers feed the FAQPage structured data and agent markdown (`homeFaqItems`).
- **Footer.** A Trust column (Security, Data Processing Agreement, Sub-processors) beside Legal (Terms, Privacy, Cookies, Legal notice); each legal page still appears once. "Sign in" was already in Explore (L-04, with `DEMO_PUBLIC`), so it is not duplicated. Methodology: see "Not done".
- **Sector pages.** With `DEMO_PUBLIC` on, the hero's primary CTA stays the free test and the secondary becomes a sector-specific pilot request ("Or request a pilot reviewed by claims experts.") to `/contact?offer=pilot-evaluation&sector={id}`; the closing card keeps the test pill and the call, and its quiet line becomes the sector's own pilot prompt plus "Request a pilot". Copy in `content/sectors/{en,es}.json` → `pilot.{cta,prompt}`. Every sector FAQ that promised the 40-question, 48-hour diagnostic now names the free test, the free account, pay as you go in the app and quoted pilots, without prices.
- **Landing closing card.** "Rather we run a forty-question diagnostic for you? Request it" became "Need answers reviewed by experts in your sector? Request a pilot" (`/contact?offer=pilot-evaluation`), so the free test leads and the contact form is the pilot path. Flag-off behaviour is unchanged.
- **Contact form, five fields.** "Request a pilot evaluation": full name, work email, company, sector, what the pilot should cover. Above it, "Prefer to try it yourself? Run the free test" (with `DEMO_PUBLIC`) and the call link. The offer comes from `?offer=` (default `pilot-evaluation`), the sector from `?sector=`. The form sends `formVersion: "pilot-request-v2"`.
- **Validator and intake, compatible.** `systemType` and `ownerRole` are optional in `lib/validators/evaluation-request.ts`; the earlier structured payload is still accepted and its choices still validated. `evaluation_request.system_type` and `owner_role` are NOT NULL (migration 030), so an unasked value is stored as `other`, and `source.form` plus the audit transition's `evaluation_request.form` record `pilot-request-v2`, so operators never read `other` as an answer. The operator summary and notification email omit the unasked lines. The acknowledgement email's "what happens next" now promises a proposed scope and a fixed price.
- **Call page.** A three-line agenda (what your assistant answers and for whom; how you check its answers today; what a test would cover and the next step) above the Cal.com scheduler. When Cal reports a booking (`bookingSuccessfulV2`), a confirmation in the visitor's language replaces the scheduler: the slot in their language and time zone, the calendar invitation, and the free test as preparation. Focus moves to it.
- **404.** With `DEMO_PUBLIC`, the free-test pill first, then "Go to the home page" and the sectors as quiet links. The removed routes (`/pricing`, `/docs`, …) keep answering 404 with this page.
- **DPA click-through in Settings (P-42).** Settings → General has a Data Processing Agreement row for every member: what it is, the record in one sentence ("Version 2026-10-11, accepted by Name (email) on October 12, 2026."; an older acceptance shows "New version"), "Read the DPA" and "Download for signature (Word)" on the public site in the person's language, and the countersigned-copy address (privacy@caudals.com, as the DPA page says). Owners get "Review and accept": a dialog with the version, the signer and one required confirmation. `GET/POST /api/evals/v1/workspaces/:id/dpa` (`lib/legal/dpa.ts`) records through L-01's `record_terms_acceptance` with document and context `dpa` (version, time, signer, locale, request id) and writes an `audit_event` `legal.dpa_accepted` with the signer's name and email at signing. Only owners accept and only the published version (`OWNER_REQUIRED`, `VERSION_CHANGED`); platform staff can read but never accept for a customer; a second accept of the current version returns the existing record. **No migration**: the function needed no schema change.

## Not done (and why)

- **Ops attaching a countersigned PDF** (P-42, managed customers). The only upload storage, `evals.artifact`, is evaluation evidence: it needs an evaluation project, expires pending uploads after seven days and has no column that ties a file to a workspace's DPA, so there is no clean path without a migration. Until a follow-up package (one migration, e.g. a `legal_document_attachment` table plus an ops upload), countersigned copies stay with privacy@caudals.com as the DPA page says. Needs a migration number from the orchestrator.
- **Blog and Newsletter in navigation** (§7.7). Not live: the newest blog post in the archive (`ops.caudals.com/api/blog`) is from 2026-08-12 (none since the spec), and the newsletter's last issue is No. 1 of 2026-07-31. They stay hidden; the condition is in PROGRESS.md §5 for the founder.
- **Methodology in the footer.** L-20 (methodology page) had not merged when L-30 rebased, so no link to a page that does not exist was added. L-20's branch adds the link itself (`footer.methodology` in Explore); it now merges into the footer with the Trust column (keep both sides).
- **Agent-facing offers.** `lib/public/evaluation-offers.ts` (llms.txt, agent markdown, home structured data) still lists the free 48-hour "Initial Diagnostic" with price 0 and the `pricing` message namespace. It is outside L-30's files and L-20 is editing `llms.txt`; worth aligning with D-06 in a follow-up so agents describe the free test and account instead.

- Prerendered public pages show the image build's flag-off state for up to five minutes after each deploy (L-04 note); the L-30 changes that depend on `DEMO_PUBLIC` follow the same rule.
