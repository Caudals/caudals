## What shipped

- **Home (P-12)** at `/workspace/home` (`components/evals/workspace-home.tsx`), first sidebar item, behind `WORKSPACE_HOME_ENABLED` (server-read; also makes Home the landing page for workspace members via `/evaluation-entry`). Cards: needs your action (the evaluations list's own stage projection through `evaluationRows`, with the next step per row; "See all" opens the list filtered), latest score per system with a three-run trend, the next scheduled run, the plan (slot for L-15's balance, no numbers of its own), shortcuts and the example evaluation link. One API request (the workspace summary).
- **Systems health (P-14)**: status (connected / needs attention), last successful check and last score columns; "Check now" (the existing connection check, now bounded to one in flight per system version and rate-limited 5 per system per 10 min, 30 per workspace per hour; editors and owners); "Fix" deep-links to re-teaching the chat (owners), updating the key or pairing the runner (`?system=<id>&fix=1`); the empty state explains the three connection types with examples. The evaluation's Connect step shows the same health block and "Check now". The Connect step's "Manage connection" link pointed to a non-existent `/workspace/systems/<id>` route; it now opens the system panel.
- **Faster review (P-17)**: free and PAYG (`plan` in `free`, `payg`) open on a 10-question spot check (spread across source pages, most severe first), then "Approve and run" (or approve only); the report is the usual preliminary report and the screen says so. Managed (and partner, unknown) plans keep the full review; the server refuses a spot check for them (`409 REVIEW_REQUIRED`). The full review adds a source-page filter, select / select all shown, bulk "Mark as checked" and "Remove selected" (new `POST /suites/:id/cases/remove`, one change, audited), inline edit (question and expected answer) and keyboard shortcuts (`j k c x e r / ?`, documented in the UI and `docs/FRONTEND.md`). Approval attribution: every approval writes `audit_event suite.approved` (approver, version, mode, question count, checked and approved ids) beside the idempotent request's `created_by`.
- **Navigation (P-15)**: ⌘K covers systems (deep links), reports, test sets and every Settings tab; breadcrumbs name the system (Evaluations › system › evaluation; Systems › system); Settings and reports remember their last tab per device. A visible Help entry in the sidebar foot.
- **Evaluations list**: a next-step hint on rows that need action and the change over the last runs.

## Production verification (2026-10-13, no customer account for agents)

- **Unauthenticated**: `GET /api/evals/v1/workspace/summary`, `POST /targets/:id/checks`, `POST /suites/:id/cases/remove` and `POST /evaluations/:id/approve-suite` answer 401 `SESSION_REQUIRED`; `/workspace/home` and `/evaluation-entry` stream the 307 to `/workspace/sign-in?next=…` with the flag off and on; `caudals.com/workspace/home`, `/admin` and `/en/pricing` 404.
- **Summary SQL on the production schema** (read-only transaction, `postgres`, counts only): the systems query with the last successful check, the reports query with each run's system and the next-run query ran in 9.0, 1.6 and 0.7 ms on the largest internal workspace (33 systems, 9 reports; 8 systems with a successful check; every report resolved to a system) and 3.7, 1.4 and 0.7 ms on another (8 systems, 18 reports, 4 systems). No active schedules exist in production, so Home shows "No runs scheduled".
- **Rate limiter**: `public.abuse_rate_limit` belongs to `caudals_app` (the app's role), so "Check now" limits are kept in PostgreSQL across app tasks (1,076 existing rows; in the disposable test database the runtime role cannot write it and the limiter falls back to memory, as designed).
- **Logs**: no `SERVICE_UNAVAILABLE` or server errors in the app, worker or scheduler in the 15 minutes after the deploy.
- **Flag**: `WORKSPACE_HOME_ENABLED='true'` in the credentials file and in the running app's runtime secret.
