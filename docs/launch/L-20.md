## Risks and follow-ups

- Docs drift: each article has an owner and a `review_by`; `lib/evals/help/review-dates.test.ts` fails once one is overdue (not in the image build, so it never blocks a deploy). L-15 (billing screens), L-19 (CI trigger, destinations) and L-14 (plans) must update `credits-and-billing`, `schedules-and-alerts` and the API reference.
- Copy found inaccurate in other surfaces, not changed here: the Terms say "the app shows your current limits" and an estimate before each run (not yet true for customers); the demo account card says "Your 8 questions, plus up to 50 more", but `lib/demo/import.ts` keeps the eight questions in the demo; "Check connection" says it "sends one harmless request", which is not true for API systems; the invitation dialog's help text speaks to operators.
- Product gaps the articles state plainly: no in-app member removal or role change for owners (Caudals does it), no schedule deletion, regression emails not sent (the notification centre and webhooks carry them).
