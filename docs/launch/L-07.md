## What shipped

- **One email system** in `lib/email/` (templates, EN/ES copy typed for parity, Paper frame, static renderer, links and switches). 27 templates in both languages: sign-up link (demo path with a one-line score summary), account exists, domain taken, password reset, invitation, eight workspace notifications, seven lifecycle steps, payment receipt, low balance, auto-recharge done and failed, credits expiring, cap reached (50/80/100 %, monthly, per-run, per-schedule), and the public demo's report and share emails. The billing templates are ready for L-12/L-15/L-18 to trigger (`renderEmail("payment_receipt", locale, props)`); L-12 had not added a receipt template when this rebased.
- **Renderer**: templates are React components rendered by a small static serialiser, not `@react-email/render`, because the scheduler (and workers) run under `--conditions=react-server`, where `react-dom/server` throws (checked on the host). A test compares its output with `react-dom/server` for every template and language. Templates sit under `lib/` because worker images ship only `lib/` and `services/`.
- **Branded transactional mail** behind `BRANDED_EMAILS_ENABLED` (server-read in the app and the scheduler): sign-up emails (`lib/evals/signup.ts`), password reset in the language of the requesting page (`lib/auth/better-auth-options.ts`, building on L-08's file), workspace notifications in each recipient's email language (`lib/evals/operations/notifications.ts`, idempotency key per delivery), the demo report email (L-03) and L-04's "send to a colleague" email, both now linking the public report on `caudals.com/{locale}/demo`. With the flag on, new workspace invitations are also emailed to the invitee (the dialog says so and still shows the link), and a bare sender address gets the display name "Caudals". Off: exactly the previous plain-text emails.
- **Email categories** (Settings → Notifications, EN/ES): in-app categories unchanged; email per category for the workspace (results and test sets, input required, failures, billing and credits for owners, regressions) and "Tips for getting started" per person. Saving records the interface language as the email language. The API accepts the old single switch from cached clients and keeps the old column in step.
- **Lifecycle job** in the evals scheduler every five minutes (`lib/evals/operations/lifecycle-email.ts`), behind `LIFECYCLE_EMAILS_ENABLED` and `LIFECYCLE_EMAIL_STEPS` (default D0–D7). Cohort: owners of live free self-serve workspaces from the last 45 days, not staff, not unsubscribed. Steps: D0 welcome; D1 if no test set; D3 if no run; D7 if no report (15-minute setup call via `CALCOM_LINK`); first report → share or book a readout; D21 re-run if no run since the first report; D30 win-back if inactive for 14 days. Madrid calendar days, Madrid working hours after D0, a sending window per step, skip on conversion, one lifecycle email per 20 hours, claim-before-send dedupe with a stable Resend idempotency key and three attempts.
- **Unsubscribe**: footer link to `/workspace/unsubscribe#<token>` (public, confirm button, token kept out of logs and the address bar) and RFC 8058 one-click headers to `POST /api/evals/v1/email/unsubscribe?token=…`; `GET` only redirects to the page.
- **Separation (spec §7.6, Leads rule 5)**: lifecycle mail is account mail from the product database. It never reads or writes the newsletter (Caudals Ops) or outreach (Warmbly) lists, and it is sent from the transactional domain, not the outreach domains.

## Migration 087 `evals_lifecycle_email`

Additive. `evals.notification_preference` gains `email_completion`, `email_required_input`, `email_failure` (backfilled as old switch AND category; default off), `email_billing` and `email_regressions` (default on). New `evals.email_preference` (per person; RLS to the person; the unsubscribe token is not in the runtime grants) and `evals.lifecycle_email` (one row per person and step; no runtime access). Functions: `lifecycle_email_candidates`, `_claim`, `_finish`, `_skip` (EXECUTE for `evals_scheduler` only), `email_unsubscribe` (runtime), and new versions of `notification_email_recipients` (adds each recipient's language and the billing and regression categories) and `notification_due_workspaces` (now also picks up workspaces whose only notice is a test set, source or export notice). The rollback restores the 061/065 functions and refuses once a lifecycle email or an opt-out exists. `scripts/evals/test-db.sh` adds a scheduler login for the fixture.
