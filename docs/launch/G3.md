## What shipped

### 1. AI-disclosure check in PDF, Word and share links (L-29)

- One mapping for every format, `lib/evals/reports/disclosure.ts` (plain module): status label, reason sentence and turn labels from the app catalogue's `aiDisclosure*` keys, so the web report, the share page, the PDF and the Word file say the same thing: "Evidence for your own assessment, not a legal determination. It doesn't count toward the score or any pass rate." / "Evidencia para tu propia valoración, no una determinación legal…", plus the Article 50 context line. No "compliant" or "certified". The web component (`components/evals/ai-disclosure-evidence.tsx`) now reads the same mapping. One new key, `aiDisclosureConversation` ("The conversation" / "La conversación"), heads the transcript in print.
- **PDF** (`lib/evals/reports/document.ts`): a numbered section after the findings, as on the web Overview: title, evidence sentence, status chip and reason, the quote with its turn, the conversation as a table (missing turns "Not captured"), the context line. **Word** (`docx.ts`): the same, after the findings.
- **Only when the run has a result, and only while `AI_DISCLOSURE_CHECK` is on where the file is made**: the web app (Word, share page, share Word), the documents worker (PDF; the flag is now passed to it) and the scheduler (the export's readable report; flag passed too). Stored files that carry the check end in `.ai` (`reports/<revision>.v3.ai.pdf`, `….v3.ai.docx`, `shares/<id>.v3.ai.pdf`), so switching the flag renders fresh copies instead of serving one made under the other setting (a share PDF made in the last ten minutes is still served, as before, so a rollout cannot loop).
- **Share links**: the status and reason travel with the `findings` section; the quote and the conversation are interaction excerpts, so they travel only with `results` (`sharedDisclosure`, used by the share exchange, `redactSharedSnapshot` for share PDF/Word, and the share dialog's preview). Without the findings, nothing.

### 2. "Export all workspace data" is complete (L-32, L-31, L-30, L-36)

`lib/evals/operations/workspace-export.ts`, format 1.1:

- `reports/<n>-<slug>/questions.json`: the questions asked about the report (L-36) with status, cited answer, cited result and finding ids, model, data routing, ledger mode and credits charged; an erased question keeps only its record (`erased_at`, no text).
- `legal/publication-consents.json`: every L-31 consent, withdrawn ones too, with signer, wording version, scope, dates, revocation and the public page (slug, dates); never the staff's pre-publication review note.
- `legal/dpa.json`: DPA acceptances (version, date, locale, request id, signer name and email from the `legal.dpa_accepted` audit) and countersigned copies **by reference** (file name, size, SHA-256, upload and removal dates, removal reason; never the storage key or the PDF, which owners download in Settings → General).
- `sources/<n>-<slug>/<revision>.cef.jsonl` (CEF `source` record: title, anchors and excerpts, the original's checksum, size and type) and `sources/<n>-<slug>/<revision>/original.<ext>` while the new `maxSourceBytes` (32 MiB per export) and the archive limits leave room; past them, or if the stored file is missing, `sources/index.json` lists the revision by reference (`original_omitted`: `size_limit`, `unavailable`). Licensed and Caudals-owned sources are listed by reference only (`not_customer_owned`).
- `audit/audit-log-001.jsonl`, `-002`, …: every `audit_event` of the workspace, oldest first, keyset-paged (microsecond cursor) and split every 20,000 entries so a long log is never one string in the scheduler's memory.
- Owner-only: the records only owners read (consents, countersigned copies, audit log, and the questions) are read **as the owner who asked** (`workspace_export.requested_by`) through row-level security, never as the service; if that person is no longer an owner when the build starts, the export fails with `export_owner_required` and nothing is stored. README (EN/ES) and manifest (`excluded`: deleted items, credentials and keys, countersigned DPA files, staff-only records; `source_limits`) updated.

The anonymous index and agent markdown stay out.
