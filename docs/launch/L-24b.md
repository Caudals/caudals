## Why mobile LCP was 5–6 s

Lighthouse's simulated LCP (Lantern) replays, on a slow 4G link with a 4× slower CPU, every request that **finished before the largest paint in the unthrottled trace**. On production the landing painted at ~485 ms, after all four preloaded fonts (330 KB), ~390 KB of script and the three stylesheets had arrived, so all of it was on the LCP path (6.3 s). The paint itself waited for the framework chunk to evaluate. The LCP element is the hero standfirst on the landing (`p.lp-sub`, Geist) and the headline on the demo (`h1.dm-h1`). FCP was 1.6 s: the gap was weight, not render-blocking work.

On every public page before the first paint (compressed): both message catalogues (31 KB); the session client, Better Auth and Sonner (~40 KB), because the public layout imported `RootDocument`, whose `AuthProvider` import put them in the layout's client entry even with `session={false}` (Next loads the script of every client component a layout's server modules import, rendered or not); the mobile menu's Radix dialog, scroll area and icons (~25 KB); the browser Sentry SDK (a 14 KB chunk and part of the 131 KB framework chunk, which is 74 KB without it), which production never gives a DSN; and four font preloads, of which only Geist sets the largest paint.

## What shipped (code only; no visible change)

- **One language, only the namespaces used.** `lib/i18n/context.tsx` no longer imports the catalogues (lookup in the new `lib/i18n/translate.ts`; `lib/i18n/messages.ts` keeps the catalogues and its API). The public layout sends `PUBLIC_SHELL_MESSAGES` (header, footer, cookie notice, 404 view; ~2 KB) in the RSC payload; pages add theirs with `<ClientMessages locale groups>` next to the client component: `demo`, `heroChatMessages(sectors)` (only the conversations shown), `steps.how|exam|improve`, `contact` + `validation`, `call`, `newsletterForm` + `validation`. `tests/i18n/public-client-messages.test.ts` renders the landing, demo, every sector page, the hub and the 404 view in both languages with `DEMO_PUBLIC` on and off, with exactly these subsets, and fails on any missing key (checked by removing one group).
- **Public document without auth.** `PublicDocument` (`components/document/public-document.tsx`) for `app/[locale]/layout.tsx`; `RootDocument` keeps the session and toasts for the internal surfaces (its `session` prop is gone); `rootMetadata` moved to `root-metadata.ts`. The contact form mounts its own `Toaster`.
- **Server-rendered sections.** Landing (hero, logos, problem, steps, FAQ, closing card), sector pages, hub, breadcrumbs and the demo frame render on the server and take `locale`/`demoPublic` props (`createScopedTranslator`, also usable in the UI harness). Hydrated: header, footer, cookie notice, hero chat, the animated figures (pipeline, failure modes, growth) and the demo. `LandingShell` is no longer a client component; momentum scrolling is its own island (`momentum-scroll.tsx`). Renamed: `home-page-client.tsx` → `home-page.tsx`, `sector-page-client.tsx` → `sector-page.tsx`, `sectors-hub-client.tsx` → `sectors-hub.tsx`.
- **Mobile menu on first use.** `components/ui/mobile-menu.tsx` (button) loads `mobile-menu-sheet.tsx` on the first tap (prefetch on pointer or focus); focus returns to the button on close. The sheet's close button became a 24 px target (WCAG 2.2; padding around the unchanged 16 px icon), found by the new a11y test.
- **Fonts.** Only Geist is preloaded. Newsreader (optical-size axis kept, founder decision) and Geist Mono load when first laid out and swap in as before.
- **Browser Sentry.** `instrumentation-client.ts` and `app/global-error.tsx` load `@sentry/nextjs` only when the build sets `NEXT_PUBLIC_SENTRY_DSN`. Production never gave the browser a DSN (the client initialised with `enabled: false`), so nothing that reached Sentry changes; server, edge and worker reporting are untouched (docs/TOOLS.md).

Result on the landing: 21 → 13 script tags, ~390 → ~176 KB of compressed script for modern browsers, 4 → 1 font preloads, framework chunk 131 → 74 KB; the HTML grew 21 → 27 KB compressed (server-rendered sections are also in the RSC payload).

## Not met, and what remains

- **Mobile LCP < 2.5 s on the landing and the demo** (landing ~3.4 s; demo 3.5–4.3 s) and **landing TBT < 200 ms** (medians 212 and 172 ms, runs 152–229 ms). After this package the simulated LCP path still holds the HTML (27 KB), the three stylesheets (32 KB), Geist (30 KB), the framework's script (~150 KB compressed: React DOM, the Next router and runtime; no app change removes it) and ~45 KB of app script, because on production's fast network the first paint (~200–400 ms unthrottled) still comes after every script has arrived. On the landing the italic Newsreader (130 KB) is on the path too: below-the-fold text (the failure-modes quote) uses it, and the browser requests it at the first layout. It also renders customer quotes in the demo report, so it cannot be subset safely.
- Options, none taken here because each changes behaviour or needs a decision: drop Newsreader's optical-size axis (founder decision, §5 of PROGRESS: −~157 KB); `content-visibility: auto` on below-the-fold sections, so their fonts load when scrolled to (changes scroll-height estimation and anchor jumps; needs its own check); Next's experimental `inlineCss` (global to the app; a local mirror got worse, production untested); or a lighter framework path for the public site.
- **Sign-up mobile LCP regressed** 1.8–2.2 → 2.9–3.2 s (runs 2.50–3.24 s) (target 2.5 s) for a reason outside this package: every app page, `/workspace/start` included, ships the evaluation app's full EN+ES catalogue in one 147 KB compressed chunk (464 KB raw; `lib/evals/messages`, grown by L-23/L-23b), up from ~104 KB in L-24's run. Same fix as here, on the app side: send the surface only the strings it reads, in one language. The CI gate still asserts 2.5 s for sign-up and would fail once the workflow is re-enabled.
- CI regression ceilings tightened (`lighthouserc.js`): mobile LCP landing 7.5 → 4.5 s, demo 7.0 → 5.0 s, landing TBT 350 → 300 ms; the targets stay as warnings.
- Pre-existing, unchanged by this package (checked on the previous image `34065ad6`): a missing public page answers 404 with Next's client-rendered error shell (`<html id="__next_error__">`) instead of server-rendered 404 HTML; the 404 view appears after hydration.

## Founder actions

## Risks

- A client component that reads a namespace its page does not send renders the key. The new Vitest suite covers the landing, demo, sector pages, hub and 404; contact, call and newsletter pages send theirs explicitly, and development logs `Missing message`.
- The first tap on the phone menu fetches three small chunks (~25 KB) before it opens (prefetched on pointer-down or focus).
- Newsreader now swaps in slightly later on slow connections (it is no longer preloaded); the final rendering is identical.
