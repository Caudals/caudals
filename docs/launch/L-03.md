## What shipped

- **Queue (`DEMO_QUEUE_ENABLED`).** A FIFO queue replaces the `busy` and `capacity` refusals. A new run waits (`queued_at` set, `started_at` NULL) and the web process admits the oldest one while fewer than `DEMO_MAX_ACTIVE` (3) runs are in progress, fewer than `DEMO_MAX_ACTIVE_WEBSITE` (2) website runs are, and a model can serve it (`lib/demo/queue.ts`, transaction advisory lock). An API run may pass a website run that waits for the browser. Visitor and per-site limits and proof of work are unchanged; `DEMO_QUEUE_MAX` (50) is a safety valve (`queue_full`). A run that loses model capacity mid-way returns to the head of the queue with its work kept; one that waits longer than `DEMO_QUEUE_MAX_WAIT_MINUTES` (360) fails as `queue_timeout`.
- **Place in line and ETA.** The run view carries its position, the slot count and the median / 90th-percentile duration of the last 50 finished runs (defaults 4 / 8 min); the page shows "You're number N in line" and "ready in about X–Y min", or an honest capacity message when nothing can run it. Running tests show "About X–Y min left".
- **Report by email.** "Email me the report when it's ready" with a consent checkbox (queued or running tests). Address and private token are stored only as an AES-256-GCM envelope (master keyring, purpose `demo_notify`); when the run ends, the email goes to that address only (private report link), then the envelope is deleted and `notified_at` set. Retries for an hour, then the request is dropped. Three requests per visitor a day.
- **Fallback model (`DEMO_FALLBACK_ENABLED`).** DGX first; a rate limit, timeout, 5xx or spent daily quota opens a two-minute circuit and the call goes to `google/gemini-3.1-flash-lite` on OpenRouter (`DEMO_OPENROUTER_API_KEY`). Every call reserves its worst-case cost in `demo.fallback_usage` under `DEMO_FALLBACK_DAILY_EUR` (5) with one conditional upsert, then settles the reported cost; the run records `model_used` and `fallback_cost_eur`. `DEMO_FALLBACK_FORCE` skips the DGX. The footnote discloses the backup model when the fallback is on.
- **Timeouts and events.** Per-phase limits (reading 5, writing 10, asking 12, grading 5 min) fail a run as `timeout_<phase>`; a finished run is never written again. `demo_started` and `demo_finished` (§4.20 properties) are emitted server-side from `lib/demo/events.ts` only, with every failure reason as `error_code`.
- **Page.** Service notice (busy with ETA, degraded, at capacity) on the start form; queue panel, ETA, email form, degraded notice and "finding the chat" tips after 60 s on the live view; EN/ES; reduced motion respected (new entrances fade only under `no-preference`).
- **Browser worker.** Serves admitted runs only, hands a re-queued run back, and handles `EVALS_BROWSER_DEMO_CONCURRENCY` demos at once (production: 2).
- **Load test.** `scripts/demo/load-test.ts`: local against fake providers on the disposable database, or production at most three runs against Caudals' own hosts.
