## What shipped

- **Migration 102 `billing_byok`.** `org_id` on `evals.provider_account`, `provider_revision` and `provider_connection` (NULL = Caudals' own provider). A trigger stamps a revision's and a connection's workspace from the account; it never changes. BYOK connections keep the provider, a per-save `key_version`, the key's state (`valid` / `quota_exceeded` / `invalid`), the model ids the key could list and revocation fields, and **no part of the key in clear** (no hint; a CHECK enforces it). Fixed endpoints per provider (`evals.byok_endpoint`); one live key per provider and workspace.
- **Isolation.** Row-level security on `provider_connection`: the admin login sees platform rows only, the inference worker platform rows plus the current workspace's own, the web runtime has no grant. Owner/platform-admin `SECURITY DEFINER` functions (`byok_connect`, `byok_rotate`, `byok_revoke`, `byok_set_route`, `byok_clear_route`, `byok_connections`, `byok_routes`) never return the envelope; `byok_report` (worker) records the key's state; `byok_revoke_for_deletion` erases keys in the deletion workflow. The web process checks the key and encrypts it; **only the inference worker decrypts**, for a reserved attempt of the same workspace, with the envelope bound to workspace, account and key version. Route guard: a BYOK revision serves only its own workspace's workspace/evaluation routes, never the platform default (`BYOK_SCOPE_DENIED`); `loadProvider` refuses a step naming another workspace's revision.
- **Key check (the only provider call when saving).** Free calls: the provider's model list (OpenAI, Anthropic, Google, Mistral) or OpenRouter's key status plus its public model list. Rejected keys are never saved; OpenRouter keys with no credit left are saved as "Out of quota". Nothing the provider answers is echoed; logs carry provider, outcome and status only.
- **Routing.** "Use your key" registers (or reuses) a workspace-scoped revision with a €0 price and upserts the workspace routes for the chosen roles (all four by default), keeping each role's web research where the model can search. Runs and generation jobs freeze it (migration 078). Reports record `methodology.data_routing` (`customer_provider`, `approved_providers`, `local_only`), shown in the web report, PDF and Word.
- **Failures (INV-11).** Provider failures on a key become `customer_key_*` reasons; the worker records the key's state, pauses the whole workflow and never switches to a Caudals key. A rejected or removed key stops later calls before any reservation. Judge and takeaway jobs wait instead of failing; "Your provider key failed: <reason>" with "Fix the key" shows on the run and on test-set preparation. Saving a working key resumes the paused work by itself (retry backoff cleared). Removing a key erases it, retires its revisions and removes the workspace's routes to it in one transaction; work paused on it is relabelled `customer_key_revoked` and its grading ends ungraded.
- **Billing.** `billing.provider_revision_rate_key` reports a BYOK revision as free of token credits: no holds, captures or shadow engine entries, estimates show "your key · no token credits"; platform meters are charged as usual. Our euro liability is 0.
- **UI.** Settings → AI models for owners where BYOK is open or a key exists (keys table with state, replace and remove; engine tasks on "Your key" or "Caudals' model"); platform admins see it above their engine settings. EN/ES.
- **API.** `GET/POST /api/evals/v1/engine/byok`, `PATCH/DELETE …/engine/byok/:id`, `PUT/DELETE …/engine/byok/routes`. Adding or replacing a key needs a sign-in within 15 minutes; removing never does and works with the flag off.
