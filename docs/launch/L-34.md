## What shipped

- **Drag and drop** (`components/evals/intake.tsx` → `DocumentIntake`): up to 50 files of the accepted types (TXT, MD, DOCX, PDF, CSV, XLSX), 25 MB each, 200 MB per evaluation. Type, size and the file/byte budget are checked before upload (`lib/evals/intake/upload-plan.ts`); copies are skipped by SHA-256 within the batch and against files already added, and `createUpload` answers a file already in the evaluation as `duplicate` (server-side, flag on). Each file has its own row, badge, upload progress (XHR), error and retry; two upload lanes; a failure never stops the batch. The picker and keyboard path stay (the zone's own input). Flag off: the classic form and the 20-file/100 MB limit, unchanged.
- **Import help centre** (`HelpCentreImport`): a help-centre or sitemap URL (+ optional path prefix, prefilled from the URL) → `POST /api/evals/v1/sources/websites/preview` → the browser worker (`processWebsitePreviewOne` → `discoverWebsitePages`, same guarded context and egress proxy as the reader, no new crawler) reads the start page or sitemap, robots.txt (RFC 9309, `lib/evals/connectors/robots.ts`; 5xx/unreachable = read nothing), the origin's sitemaps (index children on the same origin only, ≤ 12 fetches) and lists ≤ 500 same-origin pages inside the prefix, with robots/prefix exclusions counted. The person picks pages (preselected up to the cap) and sees "Reading N pages uses about N credits (1 per page)" from the price book's `web_page_read` rate. `POST /sources/websites {previewId, selectedUrls}` checks the list and the cap and creates one ordinary website source with `selected_urls`, `sitemap_url`, `path_prefix`, `preview_id`; the reader reads exactly those pages (robots re-checked, no links followed, ~4 s a page up to 10 min, `pages_read` recorded). Page cap (`websitePageCap` in `lib/billing/plans.ts`, `PlanLimits.websitePages`): 50 without plans v2 and on free, 200 on PAYG/managed/partner.
- **Scan detection**: the document worker records page count, characters and empty pages for every PDF (`pdfScanStats`); under 50 characters a page on average or more than half the pages empty → `scan_suspected`; a PDF with no text fails as `pdf_scanned` (`ScannedPdfError`). Prepare shows "This looks like a scanned document" under the file with Upload a text version / Add the web page / Leave it out; other sources are never blocked. No OCR.
- **"What we understood about your assistant"** (`ContextConfirmation`): a generation a person starts with the flag on gets an `evals.context_confirmation` request; when the inferred profile is ready, drafting waits (`needs_input`, reason `context_confirmation_required`; the cited excerpts are stored as evidence). The screen states purpose, users, main tasks, languages (named), jurisdiction, reference date, source order ("which source wins"), what it must not do (the analyst's boundaries) and open questions; low confidence (< 0.7) reads "Check this" with a warn edge; "Show where this comes from" opens the cited excerpts. Inline edits, one confirmation → a new `context_profile_revision` (author/time on the revision and the confirmation row, edited fields, audit `context.confirmed`, `context_confirmed {edited_fields}`). Skip, or 30 minutes without an answer (scheduler), keeps the inferred revision. Every generated test carries `extensions["caudals.evals/context-profile"]` (revision, confirmation, status); a report from a skipped context lists "Context not confirmed by the customer." (ES translated). Onboarding auto-starts and restarts do not wait. Confirming and editing are free.
- **Events**: `sources_added {source_kind: file|website|help_centre}` (no event for a duplicate), `scan_detected {source_kind: pdf}`, `context_confirmed {count, edited_fields}`.
- **Also**: generation accepts up to 60 sources (was 21/20); help article "Upload documents and answers" updated (EN/ES, drag and drop, import, scans, context screen); docs (ARCHITECTURE, TOOLS, DESIGN change log).

## Risks and notes

- The 1 MB text budget per website source can stop a very large import before the selected count (the meter charges pages read, never more than the estimate); `pages_read` shows it.
- A large import holds the browser slot for up to ~10 minutes (runs on the same worker wait); the plan cap and the preview bound it.
- `web-discovery.ts` (L-02) also emits `scan_detected` with `source_kind: website` for web search suggestions; intake's is `source_kind: pdf`.
- A job started by a person with the flag on waits up to 30 minutes for the confirmation; the page says so, and the notice centre shows "Needs your input".
