## What shipped

- **`/workspace/start`** (EN/ES, platform kit `AuthFrame`): work email and company, a privacy line, and one confirmation that is identical whatever happens next. Free-mail and disposable refusals show a warning with "Run the free test" linking the public demo in the person's language. Without the flag the page renders the not-found boundary; a signed-in person goes to their workspace.
- **`POST /api/evals/v1/signup/request`**: same origin, app host only, 404 without the flag. Order: visitor limit (5 an hour per HMAC visitor key) → strict 2 KB body → address classification → domain limit (5 a day) and address limit (3 a day, HMAC of the address) → `evals.request_self_serve_signup(..., 'direct', domain, rule, attribution)` → exactly one email. Every accepted request answers `{sent: true}`. The email says which of three things happened: a sign-up link, "you already have an account", or "your company already has a workspace: ask its owner to invite you from Settings → Members". A database per-address link limit answers the same way and sends nothing. Errors never log the address.
- **Blocklist** (`lib/evals/signup-domains.ts`): about 150 personal free-mail domains (including Spanish and Latin American ISPs), about 100 disposable domains, reserved TLDs and `example.*`. Matching uses the host and the company domain (registrable domain; Microsoft 365 `*.onmicrosoft.com` tenants count separately). Ops lists are read at runtime: `SELF_SERVE_SIGNUP_EXCEPTIONS` (addresses or domains; an exception also lifts the domain rule) and `SELF_SERVE_SIGNUP_BLOCKED_DOMAINS`. `none` clears a list.
- **One workspace per registrable domain** (enforced in the database functions, migration 085): while a live self-serve workspace exists for the domain (from the demo or direct, on any plan), a request returns `domain_taken`. Enrollment rechecks under a per-domain advisory lock and raises `SIGNUP_DOMAIN_TAKEN`. Demo links and exceptions skip the rule, but workspaces created from the demo still count against direct requests. Deleting the workspace through the audited workflow frees the domain.
- **Shared enrollment**: direct links finish on `/workspace/signup` with the same free plan and the L-01 Terms and Privacy acceptance, recorded with context `signup` in the enrollment transaction. The lookup returns `source`, and the page for a direct link drops the demo wording. While the flag is on, an expired link offers "Request a new link". If another colleague's link enrolled first, the page says to ask the owner for an invitation.
- **Analytics (L-02 catalogue)**: `account_created` with `acquisition: direct` and the first touch stored at request time, also copied to `evals.workspace.acquisition_attribution`. `limit_hit` events with kinds `signup_free_mail`, `signup_disposable`, `signup_rate` and `signup_domain_taken`. No new event names.
- **Sign-in**: "New here? Create a free account" links to `/workspace/start` while `SELF_SERVE_DIRECT_SIGNUP=true`; the invitation note shows otherwise.
- **Code move**: `lib/demo/signup.ts` became `lib/evals/signup.ts`. The demo request is unchanged: same SQL call, copy and event. One fix: a demo account whose demo run expired is now counted as acquisition `demo` instead of `direct`.
- **Registration rule** updated in `docs/evals/AGENTS.md` and `AGENTS.md`. Contracts are updated in `docs/ARCHITECTURE.md` (Public demo → Direct sign-up), `docs/FRONTEND.md` and `docs/TOOLS.md` (Direct Sign-up Operations).

## Migration 085 `evals_signup_domains`

The migration is additive. `evals.self_serve_signup` gains four columns:
- `signup_source` (`demo` or `direct`, default `demo`)
- `email_domain`, backfilled from the host of each existing row, with a partial index on enrolled rows
- `domain_rule`
- `attribution`

It adds `evals.self_serve_domain_taken()` (no grants) and a nine-argument `evals.request_self_serve_signup` that returns `link`, `account_exists` or `domain_taken`. The five-argument demo signature delegates to it and gives the same answers. `self_serve_signup_lookup` and `enroll_self_serve` are recreated with one and two extra output columns. Callers select columns by name, so the previous image kept working between the migration and the rollout.

The rollback restores the 075 functions and refuses while direct sign-ups exist. Both cases are tested.

Applied in production on 2026-10-12, before the push, with `scripts/launch/migrate-production.sh` (dry run first). Catalog check: `evals_runtime` can execute the four sign-up functions but not `self_serve_domain_taken`, and the one existing row was backfilled.

## Risks and notes

- Legitimate companies on free mail are refused. The mitigations are the ops exception list and the demo.
- The company-domain heuristic (`lib/demo/web.ts` registrable domain, two-letter country second levels such as `.co.uk` and `.com.es`, plus Microsoft 365 tenants) can put unrelated companies on another shared host into one slot. Ops can add an exception.
- The "domain taken" email tells the mailbox owner that their company has a workspace. This is by design, and it never appears in the HTTP response.
- The free-plan limits in the emails and pages are not restated, so L-14 (plans v2) can change them without copy drift.
- L-07 (branded emails) will restyle the three plain-text emails in `lib/evals/signup.ts`.
