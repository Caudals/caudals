## What shipped

- **`/workspace/start`** (EN/ES, platform kit `AuthFrame`): work email and company, a privacy line, one confirmation that is identical whatever happens next. Free-mail and disposable refusals show a warning with "Run the free test" linking the public demo in the person's language. 404 while the flag is off; a signed-in person goes to their workspace.
- **`POST /api/evals/v1/signup/request`**: same-origin, app host only. Order: visitor limit (5/hour per HMAC visitor key) → body (strict, 2 KB) → address classification → domain limit (5/day) and address limit (3/day, HMAC of the address) → `evals.request_self_serve_signup(..., 'direct', domain, rule, attribution)` → one email. Every accepted request answers `{sent: true}`; the email says which of three things happened (sign-up link, "you already have an account", "your company already has a workspace: ask its owner to invite you from Settings → Members"). A database per-address link limit answers the same way and sends nothing. Errors never log the address.
- **Blocklist** (`lib/evals/signup-domains.ts`): ~150 personal free-mail domains (with Spanish and Latin American ISPs), ~100 disposable domains, reserved TLDs and `example.*`, matched on host and registrable domain. Ops lists at runtime: `SELF_SERVE_SIGNUP_EXCEPTIONS` (addresses or domains; an exception also lifts the domain rule) and `SELF_SERVE_SIGNUP_BLOCKED_DOMAINS`.
- **One workspace per registrable domain** (function-level, migration 085): while a live self-serve workspace (demo or direct, any plan) exists for the domain, the request returns `domain_taken` and enrollment raises `SIGNUP_DOMAIN_TAKEN` under a per-domain advisory lock. Demo links and exceptions skip the rule; demo-created workspaces still count for direct requests. Deleting the workspace through the audited deletion workflow frees the domain.
- **Shared enrollment**: direct links finish on `/workspace/signup` with the same free plan and the L-01 Terms/Privacy acceptance (recorded with context `signup` in the enrollment transaction). The lookup returns `source`; a direct link's page drops the demo wording; an expired link offers "Request a new link" while the flag is on; the domain race shows "ask its owner to invite you".
- **Analytics (L-02 catalogue)**: `account_created` with `acquisition: direct` and the first touch stored at request time (also copied to `evals.workspace.acquisition_attribution`); `limit_hit` kinds `signup_free_mail`, `signup_disposable`, `signup_rate`, `signup_domain_taken`. No new event names.
- **Sign-in**: "New here? Create a free account" → `/workspace/start` while `SELF_SERVE_DIRECT_SIGNUP=true`; the invitation note otherwise.
- **Code move**: `lib/demo/signup.ts` → `lib/evals/signup.ts` (demo request unchanged: same SQL call, copy and event); the demo route and the L-02 analytics test import it from there.
- **Registration rule** updated in `docs/evals/AGENTS.md` and `AGENTS.md`; contracts in `docs/ARCHITECTURE.md`, `docs/FRONTEND.md`, `docs/TOOLS.md` (Direct Sign-up Operations).

## Risks

- Legitimate companies on free-mail are refused; mitigations are the ops exception list and the demo.
- The domain rule uses a simple registrable-domain heuristic (`lib/demo/web.ts`, two-letter country second levels such as `.co.uk`, `.com.es`). Microsoft 365 tenant hosts (`*.onmicrosoft.com`) count per tenant. Other shared hosts that put several companies under one registrable domain would share one slot; ops can add an exception.
- The domain-taken email reveals to the mailbox owner that their company has a workspace (by design, never in the HTTP response).
