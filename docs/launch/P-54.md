## What shipped

- **Owner side.** "Send to my vendor" (secondary, beside the CSV/Markdown exports of "Fix these first") for owners and operators on the current published revision. The dialog says what the vendor sees (N fixes and the answers behind them, with question, answer, expected answer, why and source excerpt; causes labelled hypotheses) and does not see (score, other answers, findings, methodology, anything else), that the page mentions the partner programme, offers the 7/30/90-day presets (30 by default), previews the vendor's page in a side panel, lists this report's fix-list links with "Opened N times, last on …" and Revoke, and shows the link once (`app.caudals.com/share/fixes#token=…`). The report's own share dialog labels these links "Fix list only".
- **The scope, without a migration.** A fix-list link is an ordinary bearer `share_grant` whose `permitted_fields` is exactly `["fix_list"]` (the column is free-form JSON). `createShare` refuses `fix_list` with any other field, with the workspace or a named recipient as audience, and for a report without failed answers (400 `INPUT_INVALID`); it still requires the current published revision. Expiry, revocation (`DELETE /shares/:id` with its `recovery_control_event`) and open counts (`share_access_event`, `open_count`/`last_opened_at`) are the share model's, unchanged.
- **What the link returns.** `resolveShareWithContext` returns `projectFixList()` (`lib/evals/reports/fix-list-share.ts`) for such a grant: revision id and date, the system's name, the review status and only the answers behind the three to five fixes, each through a field allowlist (no observation, source-revision, grader or other internal ids). Fixes are grouped per answer, so the vendor's page rebuilds exactly the owner's fixes (and the same CSV/Markdown) in either language from those answers. `meta.share` gains `scope` and, for a fix list, `expiresAt`. No server download: `shareExportKinds` is empty for the scope, so `/share/export` answers 404 and queues no PDF job. An older app reading the grant as report sections would show identity fields only.
- **The vendor's page** `/share/fixes` (Paper, `components/evals/vendor-fix-list.{tsx,css}`; Geist and Newsreader loaded by the page): "what this is" (who sent it and why, tested on, fixes, answers, whether a person checked the grades, link expiry; causes are hypotheses; only the fix list, not the full report; evidence, not certification; methodology link), Markdown and CSV downloads built in the browser, the numbered fixes (severity, counts, cause or symptom, source page, what to do) with their answers as expandable rows (answer, expected answer, why, missing/contradicted key facts, contradictions, unsupported claims, source quote), and the partner programme invitation (L-28): "Build assistants for your clients?" with the free test (`/{locale}/demo`) and "Ask about the partner programme" (`/{locale}/contact?offer=not-sure`), both with `utm_source=vendor_fix_list&utm_medium=referral&utm_campaign=partner_programme&ref=sr-<hash>` (the sharing workspace's L-17 referral). EN/ES with language buttons. A fix-list token opened on `/share` moves to `/share/fixes`, a report token the other way.
- **Event.** `report_shared` now carries `scope` (`report` or `fix_list`); the allowlist in `lib/analytics/events.ts` gained it, and `analyticsPath` knows `fixes`.
- **Docs.** ARCHITECTURE (the fix-list share, the event property), FRONTEND (owner dialog, the one Paper page in the evaluation group), DESIGN (§13 vendor page, change log).

## Risks and notes

- The fix list a vendor sees is computed from the snapshot when the link is opened; a new published revision of the report stops the link (as every share), and the owner sends a new one.
- Fix grouping ties are ordered by `localeCompare` in the browser; the server picks the same top five groups, so a tie at the fifth place could in theory differ between the owner's browser and the link. Not seen in the fixtures.
