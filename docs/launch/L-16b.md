## The bug

The daily reconciliation for 2026-10-14 stored 3 differences (`shadow_drift`), and L-11's shadow report for the same day 3 mismatches, which opened `billing_shadow_drift` at 00:30 UTC on 2026-10-15. Not a money or credit error (L-16.md): run `9e44f23b` of L-18's internal check workspace was admitted under a per-workspace `enforce` override (L-14) and its three answered questions charged the **real** ledger. L-18 set the override back to `inherit` at 04:56:30; 7 s later the scheduler's shadow-admission pass, which read the workspace's *current* mode (shadow), recorded a shadow admission for the run, and `billing.shadow_diff` treats every run with a shadow admission as a shadow run, so it expected three shadow meters (`success_without_action`). The run's admission mode was not recorded anywhere, so nothing could tell the two apart.

## What shipped

- **The admission mode is frozen on the run.** Migration 111 adds `evals.run.billing_admission_mode` (`off` | `shadow` | `enforce`), set by a `BEFORE INSERT` trigger and immutable afterwards (like `price_book_revision_id` in 089 and `model_routes` in 078). `withTenant` passes the process mode (`BILLING_CREDITS_ENABLED` / `BILLING_ENFORCE`, the same value `admitRun` uses) as the transaction setting `billing.engine_mode`; the trigger applies the rule of `workspaceEngineMode`: the workspace's `shadow` or `enforce` override, else the process mode, and `off` stays off. It reads the override row `FOR SHARE`, so an override change waits for a run being created and then refuses with `WORKSPACE_BUSY` (closes a small L-14 race). A writer that does not pass the setting (older code, scripts) leaves it NULL.
- **Older runs are classified by what they charged.** `billing.run_admission_mode(org, run)`: the frozen mode, else real-ledger holds, captures or meters → `enforce`, else a shadow admission → `shadow`, else unknown. In production this classifies `9e44f23b`, `2b9081fb` (both L-18) and `bff7bce4` (L-15) as enforce, `cb89dc9e` and `743a786b` as shadow.
- **Shadow admissions follow the admission mode** (`lib/billing/jobs.ts` `runShadowAdmissions`, `lib/billing/engine.ts` `pendingShadowAdmissions`): the scheduler records them only for runs admitted in shadow mode, whatever the workspace's mode is when it looks (runs without a recorded mode: their charges, else the workspace's mode now, as before).
- **The shadow diff checks each run against its own ledger** (`billing.shadow_diff`, replaced in 111; the reconciliation's `shadow_drift` reads it): succeeded units need a shadow meter only in runs admitted in shadow mode (with their shadow admission, exactly as before), and a real-ledger meter `action:unit:<case_unit_id>` in runs admitted in enforce mode on credit and free accounts (new check `enforced_success_without_action`; contract workspaces never hold credits). The report also counts the day's runs by admission mode (`runs`). Every other check is unchanged; `scripts/billing/shadow-report.ts` prints the new check without changes.
- Docs: `docs/ARCHITECTURE.md` (Billing modes, shadow diff, rollout overrides), `docs/evals/runbooks.md` (17, the two meter checks).

## Risks and notes

- Runs without a recorded mode are classified by their charges: real-ledger activity means `enforce`. That is exact for every run in production today; for a run created by a writer that bypasses `withTenant` it is an inference.
- Switching `BILLING_ENFORCE` globally while runs are in flight still splits those runs: answers after the switch are metered in the other mode and the diff flags them (`success_without_action` or `enforced_success_without_action`) as before. Switch with no run in flight, as L-14 already enforces for overrides.
- `enforced_success_without_action` is a real-money check: in enforce mode an answered question without its meter is a question we did not charge. Look the run up in the console's account view (runbook 17).
- The override `FOR SHARE` read serialises run creation with override changes only when the workspace already has an override row; the very first override of a workspace keeps L-14's original (tiny) window.
